
项目分层

```
交互入口层
    ↓
应用装配层
    ↓
Agent 编排层
   ↙          ↘
状态上下文层   能力执行层
       ↓
公共基础层
```

## 1. 交互入口层

对应：

```
cli.py
app/
input/
```

职责：

- 接收命令行、TUI 和附件输入
- 展示流式回答、工具执行状态和权限请求
- 处理会话、模型、Skills、MCP 等交互命令
- 将用户操作转换成应用层可以处理的请求

`cli.py` 是程序入口，`app/` 负责交互界面，`input/` 负责图片、文件和剪贴板附件。

## 2. 应用装配层

对应：

```
session/
config/
app/factory.py
```

职责：

- 读取模型和 Provider 配置
- 创建、恢复、Fork 和索引 Session
- 组装 Agent、Provider、工具、权限和上下文对象
- 恢复项目 Skills、授权记录和待处理状态
- 为 CLI/TUI 准备完整的运行环境

这一层解决的是：

> 一套完整的 FirstCoder 会话应该如何被创建和恢复。

## 3. Agent 编排层

对应：

```
agent/
planning/
```

职责：

- 控制模型与工具之间的循环
- 调用模型并处理流式响应
- 调度工具、权限确认和用户补充输入
- 控制工具轮数、模型调用次数和任务超时
- 管理任务计划和任务依赖
- 处理子 Agent、后台任务和 Git Worktree
- 判断任务完成、暂停或失败

这是整个项目的控制中心，但它不直接操作文件，也不直接发送厂商 HTTP 请求。

## 4. 状态与上下文层

对应：

```
context/
session/
```

职责：

- 使用 Append-only JSONL 保存会话事实
- 通过事件回放重建当前状态
- 将会话状态投影成模型输入
- 管理上下文预算
- 执行 L1～L4 分层压缩
- 归档并恢复历史工具结果
- 管理 Checkpoint 和任务恢复
- 保证工具调用与工具结果正确配对

`session/` 更偏会话生命周期，`context/` 更偏会话内容、模型上下文和状态投影，因此两者有协作但职责不同。

## 5. 能力执行与外部适配层

对应：

```
tools/
permissions/
providers/
mcp/
skills/
```

可以继续分成五部分：

|目录|职责|
|---|---|
|`tools/`|文件、搜索、Git、Shell、Python、网络、任务计划等具体能力|
|`permissions/`|对文件、Shell、网络等操作执行允许、询问或拒绝|
|`providers/`|适配 OpenAI-compatible、Anthropic 等模型协议|
|`mcp/`|接入外部 MCP Server，并转换为统一工具|
|`skills/`|发现、选择和加载项目或全局 Skills|

这一层负责真正的能力实现：

```
模型调用 → providers
工具执行 → tools
安全判断 → permissions
外部工具 → mcp
能力说明 → skills
```

## 6. 公共基础层

对应：

```
runtime/
utils/
```

职责：

- 提供取消信号和结构化用户输入请求
- 处理路径沙箱和文件访问边界
- 封装子进程、Git、JSON 和文本处理
- 提供多个上层模块共同使用的基础对象
- 避免工具、权限和 Agent 之间形成循环依赖

`runtime/` 不是 Agent Runtime 主循环，而是跨模块共享的运行时基础类型；真正的 Agent 主循环在 `agent/`。

## 目录归属汇总

```
firstcoder/
├── cli.py          # 交互入口层
├── app/            # 交互入口层、部分应用装配
├── input/          # 交互入口层
├── config/         # 应用装配层
├── session/        # 应用装配层、状态生命周期
├── agent/          # Agent 编排层
├── planning/       # Agent 编排层
├── context/        # 状态与上下文层
├── providers/      # 能力执行与外部适配层
├── tools/          # 能力执行与外部适配层
├── permissions/    # 能力执行与外部适配层
├── mcp/            # 能力执行与外部适配层
├── skills/         # 能力执行与外部适配层
├── runtime/        # 公共基础层
└── utils/          # 公共基础层
```

面试时可以精简成一句话：

> FirstCoder 分为交互入口、应用装配、Agent 编排、状态上下文、能力执行和公共基础六层；其中 Agent 层负责协调，Context 与 Session 层负责状态，Provider、Tool 和 Permission 层负责模型调用与受控副作用。






|模块|对应目录|主要职责|
|---|---|---|
|命令行入口模块|`cli.py`|解析启动参数，选择运行模式、模型、项目和会话|
|应用交互模块|`app/`|Textual TUI、流式输出、交互命令、权限确认和状态展示|
|Agent 编排模块|`agent/`|模型—工具循环、任务执行、暂停恢复、超时控制、子 Agent|
|上下文管理模块|`context/`|上下文构建、预算计算、分层压缩、归档和 Checkpoint|
|会话管理模块|`session/`|会话创建、持久化、恢复、Fork、索引和分享|
|模型适配模块|`providers/`|适配 OpenAI-compatible、Anthropic、流式响应和原生工具调用|
|工具系统模块|`tools/`|文件、搜索、Git、Shell、Python、网络和后台进程等工具|
|权限安全模块|`permissions/`|`ALLOW/ASK/DENY` 决策、作用域授权和持久化 Grant|
|任务规划模块|`planning/`|线性计划、DAG 计划、任务状态、依赖和版本控制|
|MCP 扩展模块|`mcp/`|连接 MCP Server，将外部能力注册为 Agent 工具|
|Skills 模块|`skills/`|发现、选择、加载和记录项目或全局 Skills|
|输入与附件模块|`input/`|处理文本文件、图片、剪贴板和多模态附件|
|运行时公共模块|`runtime/`|取消控制、结构化用户输入和跨模块运行时对象|
|基础工具模块|`utils/`|路径沙箱、子进程、Git、JSON、Schema 和文本处理|

可以进一步归纳为几个核心模块：

```
核心控制：
- Agent 编排
- 任务规划

状态管理：
- 上下文管理
- 会话管理

能力执行：
- 模型适配
- 工具系统
- 权限安全

扩展能力：
- MCP
- Skills
- 输入与附件

用户入口：
- CLI
- TUI 应用

公共支撑：
- Runtime
- Utils
```

面试时直接回答：

> 项目主要包括 Agent 编排、上下文管理、会话管理、模型适配、工具系统、权限控制、任务规划、MCP、Skills、输入附件和 TUI 等模块，其中 Agent 模块负责协调，其余模块分别提供状态、模型和外部执行能力。
