
结合前面的聊天记录，**我们已经讲得比较深入的是工具执行、权限、Session、多 Agent 和评测；还没有系统展开的是上下文压缩、模型请求适配、代码修改可靠性，以及异常恢复。**

这里要区分“提到过”和“沿源码完整讲过”。例如上下文压缩我们讨论过概念和状态字段，但还没有完整走完一次压缩链路。

## 最值得继续学习的模块

### 1. 上下文管理与压缩——我最建议下一步讲

我们之前讲了“记忆保存在哪里”，但还没系统解决：**历史越来越长，下一次究竟给模型看什么？**

值得完整追踪的问题包括：

- 输入预算如何计算，给输出预留多少空间？
- 最近消息、工具结果、Checkpoint 如何取舍？
- L1～L4 各自处理什么，按什么条件触发？
- 如何避免压缩后出现孤立的工具调用或工具结果？
- 如何判断压缩无效，失败后怎么处理？
- 模型仍然报上下文超长，如何补救？

它的价值非常大：**直接影响长任务的完成能力、费用和信息丢失风险。** 而且能把你已经理解的 Session、工具结果和运行状态真正串起来。

### 2. Provider 与流式协议适配——理解 Agent 如何稳定地调用模型

我们讨论过请求包含什么、第二次调用何时发生，但还没完整讲“内部请求如何变成不同模型服务接受的格式”。

重点包括：

- 内部统一消息如何转换成不同 Provider 的请求？
- 工具参数分多段返回时，如何拼接？
- 什么时候可以确认工具调用已经完整，允许执行？
- 流中断、超时、限流、格式错误分别怎么办？
- 哪些失败可以重试，哪些重试可能产生重复行为？

它的价值是：**让 Agent 不只是碰巧调用成功，而是能够稳定地跑完整任务。** 这也是后端工程能力很容易体现出来的部分。

### 3. 文件修改工具——Coding Agent 真正“动手改代码”的部分

我们深入讲过“改之前怎么审批”，但对“真正怎么改”还没有系统展开。

可以集中讲：

- `write`、`edit`、`apply_patch` 的实现差别；
- 文本匹配不到、匹配多处时如何处理；
- 补丁如何定位，多文件修改失败时会发生什么；
- 编码、换行符、路径、符号链接如何处理；
- 预览后文件又被修改，如何识别；
- 写入失败是否可能留下部分修改。

它的价值是：**模型方案正确，不代表最终落盘正确。** 这一块能解释 Coding Agent 与普通聊天机器人的关键差异。

### 4. MCP 集成——外部工具怎样真正接进来

我们只讲到了“MCP 工具按需激活”，还没完整讲连接和调用过程。

值得学习：

- 如何连接 MCP Server、获取工具列表；
- 工具名称冲突怎么处理；
- 工具搜索如何选择待激活工具；
- 调用参数和返回结果如何转换；
- 外部服务断开、超时、返回异常内容时怎么办；
- 外部工具的权限与信任边界在哪里。

它的价值是：**让 Agent 从操作本地代码，扩展到操作外部系统。** 这部分知识也适用于非 Coding Agent。

### 5. 中断、取消与异常恢复——把已经讲过的机制放进真实故障里

我们讲过后台取消、Session 恢复，但还没有统一梳理不同阶段被打断的情况：

- 模型正在输出时取消；
- 工具调用已记录，但工具还没开始；
- 文件已修改，但工具结果还没写入；
- 用户正在审批时退出；
- 进程崩溃后恢复，会不会重复执行操作？

它的价值是：**区分“会话数据恢复”和“外部操作恢复”，理解什么时候不能安全地重试。** 这是非常有深度的面试方向，也能避免把“有 JSONL”误认为“什么都能恢复”。

## 还有哪些值得讲，但可以稍后？

|模块|为什么值得学习|
|---|---|
|Prompt 构建与指令优先级|理解系统规则、AGENTS.md、Skill、任务计划和运行提示如何组合|
|测试与可观测性|理解如何定位 Agent 失败，以及如何证明一次修改没有破坏行为|
|沙箱与执行环境|权限决定“允不允许”，沙箱决定“实际上限制在哪里”；两者不能混为一谈|
|架构分层与依赖组装|结合你的重构，解释模块为什么拆开、如何替换依赖和测试|
|TUI 与交互状态|理解流式渲染、用户输入、审批和取消如何协作，但可以排在核心执行能力之后|

**我的建议顺序是：上下文压缩 → Provider 与流式协议 → 文件修改工具 → 异常恢复 → MCP。**

先把这些讲完，再选一个具体任务，从“用户输入”一直追到“修改完成并通过验证”，做一次全项目串联。这样，你掌握的就不是分散的模块知识，而是一套能够解释完整 Coding Agent 行为的体系。
