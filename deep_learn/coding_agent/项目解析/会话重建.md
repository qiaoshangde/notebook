恢复不是让旧对象“复活”，而是根据 JSONL 创建一个新的运行对象。

# 第三步：看 SessionView 怎么重建

打开：

[store.py (line 61)](E:/agent/后端agent开发资料/FirstCoder/firstcoder/context/store.py:61)

```
def rebuild_session_view(
    self,
    session_id: str,
) -> SessionView:

    view = SessionView(
        session_id=session_id
    )

    for sequence, event in enumerate(
        self.list_events(session_id),
        start=1,
    ):
        self._apply_event(
            view,
            event,
            sequence=sequence,
        )

    return view
```

这个方法只有三件事：

```
1. 创建空 SessionView
2. 读取 JSONL 全部事件
3. 逐条执行 _apply_event
```

真正需要重点看的是：

[store.py (line 70)](E:/agent/后端agent开发资料/FirstCoder/firstcoder/context/store.py:70)

```
def _apply_event(...)
```

阅读时可以画一张映射表：

```
session_created
session_metadata_updated
→ view.metadata

user_message
assistant_message
tool_result
background_notification
→ view.messages

checkpoint_created
→ view.checkpoints

task_plan_updated
→ view.task_plan

compaction_completed
→ 替换已有 MessagePart

message_part_metadata_updated
→ 修改已有 Part 的 metadata
```

这里不要先研究每个 payload 的全部字段，只问两个问题：

```
这个事件修改 SessionView 的哪个字段？
是追加新内容，还是修改已有内容？
```

## 最关键的理解

`SessionView` 不是简单筛选 JSONL。

它是 reducer 依次执行后的最终状态：

```
事件1：写入原始工具结果 A
事件2：压缩事件，把 A 替换成 B
事件3：metadata 更新事件

最终 SessionView
→ B + 更新后的 metadata
```

# 第四步：看 RuntimeState 怎么重建

打开：

[runtime_replay.py (line 12)](E:/agent/后端agent开发资料/FirstCoder/firstcoder/context/runtime_replay.py:12)

```
def replay_runtime_state(
    store,
    session_id,
) -> SessionRuntimeState:

    state = SessionRuntimeState(
        session_id=session_id
    )

    for event in store.list_events(session_id):
        _apply_event(state, event)

    return state
```

形式与 SessionView 重建一样：

```
创建空状态
→ 遍历全部 JSONL
→ 应用事件
```

但它关心的不是对话内容，而是运行控制状态。

重点看 `_apply_event()`：

```
provider_projection_consumed
→ 恢复 consumed_tool_result_part_ids

task_boundary_observed
→ 恢复 active/candidate task hash

checkpoint_created
→ 恢复 latest_checkpoint_id

compaction_completed
llm_compaction_completed
compaction_skipped
→ 恢复压缩指纹、失败和历史
```

因此两条重放可以这样区分：

```
rebuild_session_view()
回答：
“会话中有哪些有效内容？”

replay_runtime_state()
回答：
“Agent 的控制流程现在处于什么状态？”
```

# 第五步：看恢复后的对象怎样继续聊天

恢复出 `AgentSession` 以后，它不会立即把 `SessionView` 长期保存在内存中。

下一轮主模型请求时，看：

[loop.py (line 1074)](E:/agent/后端agent开发资料/FirstCoder/firstcoder/agent/loop.py:1074)

```
def _prepare_main_provider_request(...):
    definitions = self._provider_tool_definitions()

    view = self.session.rebuild_view()

    # 检查压缩
    ...

    messages = self._request_messages(
        view=view,
    )

    request = self._main_chat_request(
        messages,
        definitions,
        tool_choice,
    )

    return PreparedMainRequest(...)
```

注意这一行：

```
view = self.session.rebuild_view()
```

也就是说，恢复后的 `AgentSession` 继续聊天时，又会根据当前 JSONL 获取最新 `SessionView`。

然后进入：

[context_builder.py (line 30)](E:/agent/后端agent开发资料/FirstCoder/firstcoder/context/context_builder.py:30)

```
build_provider_messages(view, ...)
```

生成：

```
System Prompt
+ Checkpoint
+ recent tail
+ user/assistant/tool 消息
```

最后发送给模型。

所以完整闭环是：

```
恢复阶段：
JSONL
→ SessionView
→ SessionRuntimeState
→ AgentSession

继续聊天：
AgentSession
→ 再次 rebuild_view()
→ ContextBuilder
→ Provider messages
→ 模型
```
