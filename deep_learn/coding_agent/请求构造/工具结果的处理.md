

**问题：FirstCoder 中的“工具结果消费”是什么？**

我理解的“工具结果消费”，不是说模型一定理解并采用了这个结果，而是一个工程状态：某条工具结果已经被放进一次成功完成的模型请求中，模型至少已经接收过它。FirstCoder 需要记录这个状态，主要是为了上下文压缩时区分哪些结果可以安全压缩，哪些结果还必须保留原文。

完整过程是这样的：工具执行完成后，结果会以 `tool_result` 消息片段写入 Session 的 JSONL，每个结果片段都有唯一的 `part_id`。下一次构造模型请求时，系统会根据最新 Checkpoint 和当前消息计算真正有效的上下文，把其中所有工具结果的内容发送给模型；与此同时，在本地收集这些工具结果的 `part_id`，放进 `PreparedProviderRequest`。这里 `part_id` 只是本地记账信息，不会发送给模型。

当模型完整响应成功返回后，系统会把本次请求携带的工具结果 ID，与运行状态中的 `consumed_tool_result_part_ids` 做差集，找出本次第一次被消费的 `new_ids`。然后先向 JSONL 追加一条 `provider_projection_consumed` 事件，记录本次请求消费了哪些工具结果，再把这些 ID 加入内存中的 `consumed_tool_result_part_ids`，最后才把模型返回的 `assistant_message` 写入 JSONL。已经消费过的结果即使再次出现在后续请求中，也不会重复记录。

如果模型请求失败，或者流式响应中途失败，就不会标记为已消费；流式调用必须完整结束并成功组装出模型响应后才会记录。程序重启恢复 Session 时，会回放 JSONL 中的消费事件，重新构建 `consumed_tool_result_part_ids`。

所以我会把它总结为：

> FirstCoder 使用工具结果的 `part_id` 对消费状态进行持久化记账。“已消费”表示该结果已经进入过一次成功的模型请求，而不是证明模型真正理解了它。这个状态主要服务于上下文压缩：未消费结果优先保留，已消费结果才允许被裁剪、压缩或归档。

完整流程：
```
工具执行完成
→ 工具结果写入 JSONL
→ tool_result 消息片段获得唯一 part_id

构造模型请求
→ 根据 Checkpoint 和当前消息计算有效上下文
→ 收集有效上下文中所有 tool_result 的 part_id
→ 保存到本地 PreparedProviderRequest
→ tool_result 的内容发送给模型
→ part_id 不发送给模型

模型完整响应成功返回
→ 从收集到的 ID 中排除以前已经消费的 ID
→ 得到本次首次消费的 new_ids
→ 先向 JSONL 追加 provider_projection_consumed 事件
→ 再把 new_ids 加入内存的 consumed_tool_result_part_ids
→ 随后向 JSONL 写入模型的 assistant_message
```
