
# 工具筛选
在这个项目里，我会把主 Agent 的工具筛选理解为：每次请求模型前，从当前 Session 注册的工具里，按本地规则过滤一遍，再把保留下来的工具名称、描述和参数结构放进请求。比如，内部控制工具始终隐藏，思考、联网搜索和用户交互工具由运行配置控制，计划工具则在开启计划能力或者已有任务计划时展示。普通工具的列表通常比较稳定，动态变化比较明显的是 MCP 工具：模型先通过工具搜索找到需要的能力，系统将对应工具激活，后续请求才展示它们，新的用户轮次开始时再清空激活状态。这样可以避免一开始就把大量外部工具说明塞进上下文。不过，我会把工具展示和执行权限分开理解：模型看得到工具，不代表可以直接执行，生成具体调用后，仍然要经过本地校验和权限检查。

可能的追问：

1. MCP 工具搜索是怎么找到相关工具的？
2. 为什么每个新用户轮次要清空 MCP 激活状态？
3. 模型调用了未展示或未激活的工具，会怎么处理？
4. 已有任务计划时，为什么还要保留计划工具？
5. 如何测试工具展示规则和执行限制是否一致？
