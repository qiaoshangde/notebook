bm25是什么？其相较于tf-idf的优势。

```
BM25 是一种经典的关键词检索排序算法，可以理解为 **TF-IDF 的改进版**。它的核心思想还是：一个 query 里的词如果在某篇文档里出现，并且这个词在整个语料里比较稀有，那么这篇文档就应该排得更靠前。

但 BM25 比普通 TF-IDF 更适合实际搜索，主要有两个改进。

第一，BM25 对词频做了饱和处理。TF-IDF 里，一个词出现越多，分数通常会线性增加；但现实里，一个词出现 10 次不一定比出现 2 次相关 5 倍。BM25 会让词频收益逐渐变小，避免某个词重复很多次就把分数刷得很高。

第二，BM25 做了文档长度归一化。长文档天然更容易命中 query 里的词，如果不修正，长文档会占便宜。BM25 会考虑文档长度，让短文档里的精准命中也能得到合理分数。

所以可以总结为：
TF-IDF：TF × IDF
BM25：饱和版 TF × IDF × 文档长度归一化

在本项目里，BM25 用在 `keyword_search` 里，适合金融场景中的精确匹配，比如公司名、年份、财务指标、英文机构名、金额字段等。相比向量检索，BM25 对“字面必须命中”的问题更稳；相比朴素 TF-IDF，BM25 排序更鲁棒，不容易被词频和文档长度干扰。

BM25 是基于关键词匹配的排序算法，本质上是 TF-IDF 的改进。它保留了 IDF 衡量词稀有度的思想，但对 TF 做了饱和，避免词频无限放大，同时加入文档长度归一化，避免长文档天然占优。因此 BM25 在实际检索中通常比普通 TF-IDF 更稳定，尤其适合金融文档里公司名、指标名、年份、数字这类精确匹配场景。
```

Networks
```
NetworkX 图是 Python 里的一个图结构库，用来表示和操作 **节点、边、关系** 这类图数据。它不是图数据库，而是一个内存里的图计算工具。


NetworkX 图是 Python 里的图结构和图算法库，本项目用它把 LLM 抽取出来的三元组组织成知识图谱。节点表示实体，边表示实体关系，边上保存 relation 和 chunk_id。查询时不是让图直接回答问题，而是先匹配 query 相关实体，再在图上做 BFS，收集相关 chunk 作为证据。它适合离线、小规模知识图谱；如果要生产化、可视化和增量更新，通常会换成 Neo4j 这类图数据库。


LLM 从 chunk 抽取三元组
→ 用 NetworkX 构建实体关系图
→ 保存成 knowledge_graph.json
→ 查询时匹配相关实体
→ 从实体出发做 BFS 多跳遍历
→ 找到相关 chunk
→ 返回 evidence 给 LLM

```

```
    # Step 1: 实体匹配 — query 向量与所有实体向量做内积，取 top-5 种子实体
    q_vec = encode([query])                          # BGE-M3 编码
    scores = entity_embeddings @ q_vec.T             # (N_entities,)
    seed_entities = top_k_by_score(scores, k=5)      # [(entity_name, score), ...]

    # Step 2: BFS 图遍历 — 从种子实体出发，1-2 跳遍历，收集关联 chunks
    chunk_scores = {}
```
